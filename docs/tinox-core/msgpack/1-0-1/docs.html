class MsgpackReader

* Cursor over a byte array for decoding (issue #136). Every read * checks bounds before advancing; once `failed` is set (EOF mid-value, * or a declared length exceeding what's actually left in the buffer), * every subsequent read is a safe no-op returning 0 instead of * indexing past the end -- kein Silent-Garbage in the crash sense: * a truncated/malformed input never reads out of bounds or loops * proportionally to an attacker-declared length that vastly exceeds * the real buffer (the same declared-length-vs-actual-size amplification * shape runtime.c's httpConnReadN/httpServerReadRawBytes fixes were * for, issue #111, just here in the decoder's own bounds checks * instead of an allocation). It does NOT try to distinguish "genuinely * decoded a nil value" from "decode failed" in the returned * MsgpackValue -- same as this stdlib's other self-contained-buffer * parsers (Toml::parse, Yaml::parse, Xml::parse, Csv::parse), which * don't expose a separate ok flag either; Msgpack::decode's contract * is "never crashes, never hangs," not "always reports success/failure."

class MsgpackValue

* A dynamically-typed MessagePack value -- mirrors tinox.core.json's * JsonValue API shape (isString/getString/isInt/getInt/isArray/ * asArray/isObject/getField/... same names) since MessagePack's data * model is the same object/array/string/int/float/bool/null tree * JsonValue already represents, just with a compact binary wire * format instead of text. Unlike JsonValue (a C-backed opaque * handle), this is a plain Tinox tagged union: construct one * directly via a struct literal for encoding (e.g. * `MsgpackValue { kind: "string", stringValue: "hi", intValue: 0, * floatValue: 0.0, boolValue: false, arrayValue: [], objectValue: * Map::new() }`), the same convention tinox.core.toml's TomlValue * already uses. EVERY field must be given (Bug 130: an omitted field * left the corresponding heap slot as uninitialized garbage) -- only * `kind` and the one field it selects are ever actually read, the * rest are inert placeholders. * * Map keys are always String (matching JsonValue's object model) -- * MessagePack itself allows any value as a map key, but a decoded * map with a non-string key fails the whole decode rather than * silently coercing or dropping it (see MsgpackReader.failed).
