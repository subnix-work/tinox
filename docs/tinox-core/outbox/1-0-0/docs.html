class Outbox

* Writing side of the transactional outbox. add() stores the message in table `tinox_outbox` with * the ORM, i.e. on the connection of the caller's @Transactional method: the message is committed * or rolled back together with the business data, never separately. Nothing is sent here.

class OutboxDispatcher

* Publishing side of the outbox: reads pending records (oldest first, 50 per batch), publishes each to * its queue with the record's messageId as AMQP message-id using publisher confirms, and marks it sent * only after the broker confirmed it. * * Delivery is AT-LEAST-ONCE. If the process dies after the broker confirmed but before the record is * marked sent (or the confirm is lost), the record is published again after a restart, with the same * messageId: consumers must deduplicate on it (IdempotencyWindow091 or a unique key in their database). * No committed record is lost: a record stays pending until a confirm was seen. Failures are retried with * exponential backoff (backoffMs * 2^attempts, capped at 60 s) and parked after maxAttempts, so nothing * retries forever. Order is by id, but a record in backoff is overtaken by later ones.
