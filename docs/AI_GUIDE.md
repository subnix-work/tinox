# Tinox compact guide — compiler 2.4.0

Generated by `make docs-generate`; checked by `make docs-check` and `make check`.
The byte/word measurement and 8192-byte budget live in
[current/guide-size.json](current/guide-size.json). This is current guidance;
[CLAUDE.md](../CLAUDE.md) also contains historical debugging notes.

Use one top-level class/interface/enum per file, named exactly like its type.
The entry point is `class Main` in `Main.tnx` with
`fnc main() -> Int32`. Return `0` for success. `fnc` declares static methods;
`fn` declares instance methods. Call static methods with `Type::method()`;
call instance methods with `object.method()`. Use `let` for bindings and `var`
for mutable bindings. Statements end with `;`. Types include `Int64`, `Int32`,
`Float64`, `Bool`, `String`, `Nothing`, `List<T>` and `Map<K, V>`.
Prefer annotations for supported wiring and generated accessors.

`basic/Main.tnx` (checked stdout: 'Hello, Tinox!'):

```tinox
class Main
{
    fnc main() -> Int32
    {
        let name: String = "Tinox";
        println("Hello, " + name + "!");
        return 0;
    }
}
```

`accessors/Main.tnx` (checked stdout: '42'):

```tinox
@Getter
@Setter
class Main
{
    var count: Int64 = 0;

    fnc main() -> Int32
    {
        let counter = new Main();
        counter.setCount(42);
        println(counter.getCount());
        return 0;
    }

    @Test("generated accessors preserve values")
    fn testAccessors() -> Bool
    {
        this.setCount(42);
        return this.getCount() == 42;
    }
}
```

These annotation targets and positional argument counts come directly from the
validator. The examples above compile and run; the accessor `@Test` also runs.
Other annotations may impose additional argument types, imports and runtime
requirements; registry acceptance alone does not establish execution support.

| Annotation | Targets | Arguments |
| --- | --- | --- |
| @Getter | Class, Field | 0–0 |
| @Setter | Class, Field | 0–0 |
| @Test | Method | 0–1 |

Feature status: the entry point, static/instance calls, accessors and `@Test`
above are executable examples. `case` is reserved; match arms start with patterns
directly. Avoid assuming execution support from parser acceptance alone (for
example, traits or generic bounds). This guide makes no experimental feature a
default recommendation; consult the source API, regression tests and package's
immutable version page for limitations. Historical prose may lag the compiler:
channels have runtime/regression coverage despite older SPEC caveats.

For a project, run `tinox new demo`, then `tinox check`, `tinox run` and
`tinox test` inside `demo`. Put dependencies in `tinox.toml` with explicit
`group`, `artifactId`, `version`, then run `tinox install`. Package versions
are independent of the compiler version. The current checkout's exact package
versions and dependency/document links are in
[current/packages.json](current/packages.json); this is an inventory, not a
claim that every compiler/package version combination has been tested.
Canonical examples here are checked with compiler 2.4.0 and
require no extended packages. Use root-manifest `[[overrides]]` for unpublished
package source (see [README](../README.md)).
